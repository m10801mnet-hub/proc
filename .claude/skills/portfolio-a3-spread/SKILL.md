- 1作品＝6pにしない。全体48pを守り、強い作品に厚みを寄せる。

## 写真ルール
1. 実物写真は**真正面（または図面と同じ投影方向）**を最優先で選ぶ。図面と同アングルで並ばない写真は比較見開きに使わない。
2. 日付が写り込んだ写真（`TimePhoto_YYYYMMDD_*.jpg` 等）はトリミングで日付を除去。A4縦比率（1:1.414）を保って切り出す。
3. 写真は作品ごとのフォルダ（`portfolio_photos/01_ソフトクリーム/` 等）で受け取る。振り分け推測はミスの元。
4. キャプション帯は下部54mm・78%不透明の黒帯。図面側：縮尺／使用ソフト／決めたこと。実物側：規模・期間・担当・素材工法・成果（数字1行）。

## 生成手順
1. `scripts/build_portfolio_48p.py <出力.pptx>` で48pのPPTXを生成（python-pptx）。写真枠は名前付き図形 `IMG_<番号>_DRAWING / _REAL / _STEPn / _DETAIL_*`。
2. 写真の流し込み：図形と同位置・同サイズで `slide.shapes.add_picture` し、中央クロップで A4 比に合わせる（PIL で事前トリミング）。
3. PDF化：`soffice --headless --convert-to pdf`（`libreoffice-impress` が必要）。
4. A3見開きPDF：PyMuPDF で2ページずつ横並び（1190.55×841.89pt）。
```python
import pymupdf as fitz
src=fitz.open("p.pdf"); pw,ph=src[0].rect.width,src[0].rect.height; out=fitz.open()
for i in range(0,len(src),2):
    pg=out.new_page(width=pw*2,height=ph)
    pg.show_pdf_page(fitz.Rect(0,0,pw,ph),src,i); pg.show_pdf_page(fitz.Rect(pw,0,2*pw,ph),src,i+1)
out.save("spread.pdf")
```
5. 低解像度PNGで全見開きを目視確認してから納品。

## 既知の落とし穴
- Google Drive の `download_file_content` は10MB上限。写真入りPPTXは取得不可 → GitHubリポジトリに作品別フォルダで上げてもらう（1ファイル25MBまで）。
- クラウド環境から `drive.google.com` は接続拒否。ユーザーPCのフォルダにも直接は書けない → 成果物は SendUserFile で渡し、保存先を伝える。
- python-pptx の日本語は `a:ea` に Yu Gothic を明示（スクリプト対応済み）。プレビュー時は IPAGothic に置換される。
- `pypdf` は環境により cffi エラー → PyMuPDF を使う。
